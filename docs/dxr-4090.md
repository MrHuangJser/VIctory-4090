# NVIDIA RTX 4090 D DXR 1.1 Hardware RT Core Bridge (Phase 1)

## 背景与目标

Xbox Series (RDNA2 / GFX10) 着色器使用 AMD 特有指令 `image_bvh_intersect_ray` 与 `image_bvh64_intersect_ray` 在着色器内部的手动 while 循环中遍历 BVH4 树。
原版 `Victory`（面向 RDNA2/通用宿主）在 `crates/victory-shader/src/emit/intersect.rs` 中将单条 `image_bvh*_intersect_ray` 指令降级为纯算术 DXIL 代码（Box32 AABB slab 测试 + 5 比较器距离排序网络 + 4 槽位三角形求交），全部跑在 **CUDA Cores（通用 ALU + 显存加载）** 上，完全没有用到 NVIDIA RTX 4090 D 的 **第 3 代 Ada RT Cores**。

本阶段在分支 `main-4090` 上完成 **Phase 1：DXR Tier 1.1 加速结构桥接基础设施与硬件实测基准**，打通以下核心链路：

1. 运行时探测与接口暴露（`crates/victory-gpu/src/host.rs`）
   - 在 `Host::new` 中查询 `D3D12_FEATURE_D3D12_OPTIONS5`，检查 `RaytracingTier >= D3D12_RAYTRACING_TIER_1_1`。
   - 提供 `Host::device5()`、`Host::dxr_tier11()`、`HostList::list4()`。
2. GPU 侧 RDNA2 BVH4 → Ada Native BLAS/TLAS 转换管线（`crates/victory-gpu/src/dxr.rs`）
   - `EXTRACT_TRIANGLES_CS`：在 GPU Compute Pass 中直接解包 RDNA2 64 字节三角形节点（5 顶点 + 字节 60 的槽位/绕序控制字节，`TRIANGLE_VERTICES = [[0,1,2],[1,3,2],[2,3,4],[2,4,0]]`）为紧密 `float3` 三角形缓冲区。
   - `CONVERT_INSTANCES_CS`：在 GPU Compute Pass 中将 128 字节 RDNA2 TLAS 实例记录转换为 64 字节原生 `D3D12_RAYTRACING_INSTANCE_DESC`。
   - `DxrBridge::build_blas_from_rdna_nodes` / `DxrBridge::build_tlas_from_instances`：通过 `ID3D12GraphicsCommandList4::BuildRaytracingAccelerationStructure` 构建 Ada 原生 BLAS / TLAS，并由 `create_tlas_srv` 创建 `RaytracingAccelerationStructure` SRV。
3. 运行时 BVH 结构观测挂钩（`crates/victory-gpu/src/memory.rs` + `crates/victory-gpu/src/dxr.rs`）
   - 在 `VICTORY_DXR=1` 启用且宿主支持 DXR Tier 1.1 时，`Memory::land` 与 `Memory::ready` 会通过 `read_header` + `note_structure` 登记重建的 RDNA2 BLAS/TLAS 结构头信息到 `DxrRegistry`。

## 本机实测数据（NVIDIA GeForce RTX 4090 D）

测试环境：
- GPU：NVIDIA GeForce RTX 4090 D（Ada Lovelace，24 GB VRAM，DXR Tier 1.1，Driver 621.24）
- DXC：`F:\GTA_6\tools\dxc\1.9.2609\bin\x64\dxc.exe`（Shader Model 6.6 `cs_6_6`）
- 主机内存：32 GB（31.6 GiB 物理内存）

### 1. 几何与求交正确性验证 (`dxr_tier11_rdna2_to_ada_blas_tlas_matches_software_bvh`)

- 测试内容：构建 2 个包含全部 4 种三角形槽位 (`k = 0..3`) 与非平凡 `(i, j)` 顶点旋转、2 个带旋转平移矩阵的实例的 RDNA2 BVH4，在 GPU 上转换为 Ada BLAS/TLAS 并通过 SM 6.6 `RayQuery` 遍历 12 条多方向光线，与 `victory_shader::bvh::triangle` CPU 参考结果逐一比对。
- 结果：**PASSED**（`0.41 s`）— 全部 12 条光线在 Hit/Miss、`instanceID`、`hitT` 与重心坐标上完全一致。

### 2. 1,048,576 条光线硬件加速对比基准 (`bench_rt_core_vs_software_bvh`)

测试场景：`16` 个实例 × `4,096` 个叶子节点（`16,384` 三角形/实例），合计 **`262,144` 个三角形**，发射 **`1,048,576` 条光线**（`785,224` 条命中）。对比对象均在同卡上以 D3D12 GPU Timestamp 计取 9 轮中位数：
- **Software RDNA2 BVH4 (CUDA Cores)**：在同一份 RDNA2 BVH4 缓冲区上执行 Box32 排序栈遍历 + 水密三角形求交（`-Gis` + `precise`）。
- **Hardware Ada RayQuery (RT Cores)**：执行经 `DxrBridge` 构建的原生 Ada BLAS/TLAS + SM 6.6 `RayQuery::TraceRayInline`。

| 指标 | 实测结果 |
| :--- | :--- |
| RDNA2 → Ada BLAS 构建（4,096 节点 / 16,384 三角形） | **0.250 ms** |
| RDNA2 → Ada TLAS 构建（16 实例） | **0.042 ms** |
| 软件 BVH4 遍历耗时（CUDA Cores，1M 光线） | **1.381 ms** (`759.1 MRays/s`) |
| 硬件 `RayQuery` 遍历耗时（Ada RT Cores，1M 光线） | **0.068 ms** (`15515.2 MRays/s`) |
| **RT Core 遍历加速比** | **20.44x 更快** |
| 非掠射边缘光线真值差异 (`true_mismatches`) | **0 / 1,048,576** |
| 极窄三角形掠射边缘差异 (`edge_grazing_diffs`, barycentric < 1e-4) | **135 / 1,048,576 (0.013%)** |

> 说明：135 条差异经逐条检查（`min(bx, by, 1 - bx - by)` 为 `0.000000..0.000002`）确认为硬件 RT Core 固定点边缘量化与 FP32 三角形求交在亚 `1e-5` 轮廓边界上的正常微小数值容差，非变换矩阵或包围盒错误；其余 `99.987%` 光线零偏差一致。

## Phase 2 路线图（真正接入游戏渲染循环）

Phase 1 已验证硬件加速比与转换链路；要让实际游戏帧开始使用 RT Cores，Phase 2 需要完成以下三项连接工作：

1. **实时 BLAS/TLAS 同步与增量构建 (`crates/victory-gpu`)**
   - 接入 `VICTORY_BVH_BUILDER=1` 与 `Memory` 中实际提交的 RDNA2 BLAS/TLAS 缓冲，在计算调度前基于版本/地址哈希增量重建 Ada BLAS，每帧（或按更新）异步重建 TLAS（如基准所示，单实例 TLAS 仅约 0.04 ms 量级）。
2. **`RaytracingAccelerationStructure` 描述符绑定 (`crates/victory-gpu`)**
   - 当含光追的 Compute Dispatch 绑定旧的 RDNA2 TLAS 缓冲区/地址时，通过 `create_tlas_srv` 在宿主着色器可见堆中为其分配并绑定原生 TLAS SRV。
3. **着色器级 `RayQuery` 循环替换 (`crates/victory-shader`)**
   - 在 `victory-shader` 中为这 64 个带 `image_bvh*_intersect_ray` 的 CS 增加结构化遍历循环模式匹配：将“栈循环 + Box32/Tri 节点迭代 + `image_bvh*_intersect_ray`”整段替换为 SM 6.6 `RayQuery<RAY_FLAG_NONE>::TraceRayInline(...)` 调用，消除数千条软件遍历 ALU 指令并显著缩短 DXIL 体积与 PSO 编译时间。

## 对“渲染压力、渲染效果、FPS”的客观评估

1. **渲染压力会变小吗？—— 会（在光追密集场景下非常显著）**
   - 原版方案将全部 BVH 遍历与射线求交挤在 CUDA Cores（普通着色器算术单元 + L1/L2 纹理与原始缓冲读写）上，还会大幅拉高寄存器压力（Lowering 后的软件栈与多组浮点数组会降低 SM 占用率）。
   - 实测接入 RT Cores 后，相同 104 万条光线的遍历延迟从 `1.381 ms` 降至 `0.068 ms`（**20.44x 加速**），把光追从 CUDA Cores 彻底卸载到 RTX 4090 D 闲置的专用 RT Core 硬件单元上，同时释放大量显存带宽与寄存器给光栅化和后处理 Pass。
2. **渲染效果会更好吗？—— 默认等价保真，更高画质需利用富余算力解锁**
   - 把“软件算术 BVH 遍历”换成“RT Core 硬件求交”本身是在做**等价几何求交加速**：画面光照逻辑（Ray count、Denoiser、Probe 分辨率）仍由游戏原本的着色器控制，因此不会凭空改变材质或新增原本没有的光追特效；唯一改善在于硬件水密求交可避免软件浮点截断带来的极少数边缘漏光。
   - 当后续 Phase 2 释放出显著的 GPU 耗时空间后，可以在此基础上安全拉高游戏画质设置/分辨率缩放，间接获得更好观感。
3. **FPS 会更高吗？—— 稳态光追瓶颈会明显提升；但当前开场低帧率主要受限于另一组瓶颈**
   - 从本机最新实机日志 `F:\GTA_6\captures\victory-20261126-115602.log` 可以看到，开场处于约 **`2.8–3 fps`（`~321–359 ms/frame`，1680 draws/frame）**，且进程 Private Bytes 达到 **`29.7 GB`（Working Set `18.6 GB`）**。
   - 这个阶段的主瓶颈是：**首次着色器/PSO 实时编译卡顿、资源首次上传与 32 GB 物理内存紧张导致的换页抖动**，而不是单纯光追像素/计算着色器跑满。
   - 因此：只有当 **（a）着色器与 PSO 完成预热 +（b）32 GB 内存占用可控 +（c）Phase 2 将 64 个光追 CS 切换到 RT Core** 三者叠加后，稳态游戏场景的 FPS 才会获得可观提升；单靠 Phase 1（仅注册监控，尚未替换 CS 遍历代码）不会立刻改变游戏帧率。

## Phase 2 进展（实时 Arena 桥接与原生 SM 6.6 `RayQuery` 发射器）

截至当前提交，Phase 2 已完成两条关键基建并在 **RTX 4090 D** 上完成实机验证：

1. **Phase 2A — GPU Arena BVH 遥测与 Arena Header 原生桥接（`crates/victory-gpu`）**
   - `Memory::land` 与 `Memory::ready` 已接入 `dxr::note_packed_structure` 与 `dxr::note_built_structure`，当 `VICTORY_DXR=1` 开启时持续统计静态打包与 GPU 动态构建（含 `XboxBvhBuilder`）的 BVH 标题地址及 Arena 偏移。
   - `DxrBridge` 新增 `build_blas_from_arena_header` 与 `build_tlas_from_arena_header`，可直接从 Arena 头部读取 `node_count`、`primitive_count`（BLAS）或 `instance_count`（TLAS）解析并上传生成原生 Ada BLAS/TLAS（已通过单测 `dxr_phase2_arena_header_to_ada_blas_tlas` 校验）。
2. **Phase 2B — 无 `dxc.exe` 原生 SM 6.6 `RayQuery` DXIL 发射器（`crates/victory-shader`）**
   - `victory-shader::emit::shader` 新增 `SLOT_TLAS = 252`（绑定 `RaytracingAccelerationStructure` 于 `space1, register(t252)`）、`flags::RAYTRACING_TIER_1_1`（`1 << 25`）、`Shader::tlas_handle()` 与 `SFI0` 位 `0x10_0000`。
   - 新增 `crates/victory-shader/src/emit/rayquery.rs`，直接发射 SM 6.6 `RayQuery` bitcode/intrinsic（`dx.op.rayQuery_Allocate`、`TraceRayInline`、`Proceed` 及 `Committed_*` 状态/实例/图元/光线 `t`/重心坐标读取）与冒烟着色器 `build_rayquery_smoke_cs()`。
   - **双重实证通过**：Windows SDK `dxil.dll` 验证通过（`emitted_rayquery_smoke_cs_validates_with_dxil_dll`），且无需任何外部 `dxc.exe` 编译即在 RTX 4090 D RT Cores 上实测命中目标三角形（`dxr_phase2_victory_shader_emitted_rayquery_runs_on_rt_cores`：`hit=1, t=4, inst=99, bary=(0.4000, 0.3000)`）。
3. **Bindless 非对齐 CBV 抢救同步落地（`crates/victory-gpu/src/descriptor/host.rs`）**
   - 针对实机日志中高频出现的 `constant buffer not 256-byte aligned on the host`（可能影响序章蒙皮/面部形态融合权重常量读取），`make_twinned` 现通过每帧轮转的 4 MiB 256 字节对齐上传 Slab 拷贝抢救非对齐常量缓冲数据，替代原先的零描述符回退。

## Phase 3 进展（实机分页 Arena 原生 Ada BLAS/TLAS 运行时构建引擎）

针对实机中 RDNA2 BVH 跨越非连续 64 KiB `Memory` 分页 Arena、且解压/动态构建头部仅驻留于 GPU 显存的约束，Phase 3 已在 `crates/victory-gpu/src/dxr.rs`、`memory.rs`、`host.rs` 完成完整零停顿 GPU 运行时接管引擎：

1. **三套分页 Arena `cs_5_1` GPU Compute 管线（`DxrBridge` + `DxrPagedHeap`）**
   - 独立维护 4096 槽位 Shader-Visible SRV 描述符堆（按需增量同步 `Memory::copies` 原始缓冲视图，空槽预填零描述符防越界），所有读写直接查询 `Memory` 实时页目录 `directory`。
   - `INSPECT_HEADERS_PAGED_CS`：每帧通过 3 槽位无锁 Fence 环形缓冲异步读回最多 128 个静态/动态候选地址的 64 字节 GPU 头部（零流水线停顿），过滤 `XboxBvhBuilder` 中间/暂存缓冲并验证有效未压缩 BLAS/TLAS；并在首次发现活跃 TLAS 时采样打印首条 128 字节实例布局（`dwords 0..15` 与 `dwords 16..31`）以供实机验证矩阵槽位。
   - `EXTRACT_TRIANGLES_PAGED_CS`：直接从跨页、跨 Arena 的 64 字节 RDNA2 三角形节点提取 `float3` 顶点（未映射页安全写 `qNaN`），配合**全局复用的 `vb_scratch` / `as_scratch`** 彻底消除单 BLAS 暂存显存膨胀。
   - `CONVERT_INSTANCES_PAGED_CS` + **`BlasMapBuffer` GPU 哈希表**：在 GPU 侧通过 16,384 槽开放寻址哈希表（`(blas_addr >> 8) -> ada_blas_va`）实时解析每条 128 字节实例（含跨 64 KiB 页边界处理），未就绪 BLAS 自动置零 mask 剔除并原子统计 `resolved / culled`，全程零 CPU 实例回读。
2. **帧预算与显存上限控制（`DxrRuntime` 接入 `Host::submit`）**
   - 在 `Host::submit` 提交路径（异步 `late` 与同步路径）以独立 `ID3D12GraphicsCommandList4` 串行尾挂于游戏列表之后、每帧最多执行一次，与游戏命令列表状态（PSO/堆/根签名）完全隔离。
   - 默认每帧最多构建 `16` 个 BLAS（`VICTORY_DXR_BUILDS_PER_FRAME`）、Ada BLAS 缓存上限 `512 MiB` LRU 淘汰（`VICTORY_DXR_VRAM_MB`）+ 联动 `Memory::gone` 延迟回收，双缓冲 Ping-Pong 构建实时 Ada TLAS 并原子更新 `ACTIVE_TLAS_VA`；可通过 `VICTORY_DXR_LIVE=0` 一键回退至 Phase 2 被动观测模式，`VICTORY_DXR_INST_MAT=0|1` 切换实例矩阵槽位。
3. **RTX 4090 D 实机硬件验证通过**
   - `dxr_phase3_paged_multi_arena_blas_tlas_matches_software_bvh`（跨 2 个独立 Arena + 跨 64 KiB 页边界 BLAS/TLAS + GPU 哈希表解析与未建 BLAS 剔除 + `victory-shader` 原生 SM 6.6 `RayQuery` RT Core 执行）：**PASSED**（`resolved=1, culled=1, hit t=4, inst=77, bary=(0.4000, 0.3000)`）。
   - `phase3_header_validation_filters_packed_and_corrupt`：**PASSED**。
